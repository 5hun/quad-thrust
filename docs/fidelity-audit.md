# 原作照合ガイド

照合の基準は同梱の `HOVER_SOURCE` と `HOVER120`。現在の相違点、ブラウザ向けに採用している仕様・近似、未対応事項は [READMEの「移植内容と原作との差」](../README.md#移植内容と原作との差) にまとめている。

## 実装・照合時の注意点

### 整数演算とコース形状

- Cの32bit整数、16bitの代入、算術シフト、整数除算、オーバーフローのラップを区別する。JavaScriptの倍精度演算や単純な符号比較では同じ結果にならない場合がある。特に `car_resistance` は減速前後の慣性の積を32bitで評価する。
- コース生成には角度表と `sqr_i`、TMDの16bit頂点・整数法線を使う。区間の終端は次区間の始端と同一とは限らない。描画・接地・床裏面・斜面力などが同じ頂点を参照する必要がある。
- 区間選択は `before` / `next` 接続と半平面判定、セル選択は `car_getplate` の6段階探索と境界上の比較規則に従う。近接・交差する別の路面へ判定が移らないよう注意する。
- 道路幅の外側の斜めタイルも接地対象になる。外側の落下基準は斜面の延長面ではなく、原作の頂点高さと5000+2048のオフセットを使う。バンク時の外壁の張り出しは三次元の幅ベクトルで扱う。
- 移動位置の `posr` は1/4原作単位の整数値で、表示・次の判定には `posr >> 2` を使う。負値の丸めも比較対象にする。

### 更新順序・落下・壁応答

- 床効果は更新前の `grip` を読み、浮遊・着地処理後に `grip` を更新する。CPUの `lev>0` にはプレイヤー用の着地反発・浮遊クッションを適用しない。`car_enemy` は `lev>0` で `car_bank` を呼ばない。
- 落下開始フレームも重力・姿勢・移動を進める。影の表示フラグは新たに負の `over` が設定される前に評価する。落下中は最後の区間・セルと平面を保持し、下にある別の路面へ接地対象を切り替えない。
- 負の `over` でも `car_chipeffect` の常時効果は有効で、最後のセルと更新前の `grip` により `d`・`*`・`B`を処理する。ダメージ床の対象は `lev` ではなく機体の枠番号で決まる。`over=0` のときだけ実行する `P` / `J` / `>` / `s` / `g` などの侵入時効果とは分ける。
- 落下中は警告音と低エネルギー警告点滅を停止するが、床ダメージ音・床属性の点滅は常時効果に従う。速度に応じた風音を残し、ブースター音は解放する。
- コースアウトは `over=-64*4` から終了へ進む。`SND_BOMB` は `over>64` の破壊演出で発音し、コースアウト終了では鳴らさない。
- 壁判定では現在区間の頂点・整数法線と16bit / 32bit演算を使う。左右とも外側左端の辺へ慣性を射影する。CPUはmode 1の内側判定後、mode 0の補正を接触がなくなるまで繰り返す。
- ゴール後の `lev=0` は壁の音・破片を抑えるが、押し戻しとダメージは維持する。ゴールしたフレームでは `goal_count` を直ちに壁応答へ反映し、呼出しはそのフレームの `car_action` のmode 0、次フレームから `car_enemy` のmode 1となる。

### 姿勢・描画・音声

- 姿勢と推力は前フレームの4.12行列を使う。機体の `status`、影の `statusk`、前回の `statusb` を区別し、行列はフレーム終端まで保持する。影は独立した22単位ずつの姿勢補正を行う。
- 行列のQuaternion化・正規化、角度の一律クランプ、空中ロールを滑らかに0へ戻す処理は原作の整数挙動を変える。現在の三角関数は4.12へ量子化した生成値であり、SDK実装との一致は未検証。
- カメラの高さ850と追従距離には俯仰・旋回・バンクを含む回転を適用し、開始時の距離も同じ軸で扱う。床のテクスチャ面と暗いV字形の床裏面は別プリミティブである。
- 提供VABのキー範囲に対応するトーンがないHOVER2（プログラム127・ノート28）、SAMPLE16（同51）、SELECT（同36/56）は、原データの範囲判定に従って発音しない。

## 検証範囲

### 原作C関数との直接比較

各 `npm run test:source-*` は、同梱のC関数本体を取り出して一時ディレクトリでコンパイルする。実行には抽出済みデータ、Python 3、`cc`が必要。PS1の描画・音声APIは呼ばないスタブとし、Cのintを32bit、整数オーバーフローをラップする設定で比較する。

| コマンド                 | 比較対象                                                              | 比較範囲・限界                                                                                                                                                     |
| ------------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `test:source-geometry`   | コース頂点・法線、区間／セル選択、接地面高さ・外側の落下基準          | 全9コース・205区間、頂点40,648個、法線30,920個、境界とその±1原作単位を含む45,680点。静的な接地問い合わせの比較である。                                             |
| `test:source-walls`      | `car_wallcheck`、整数移動、CPU用内側判定・補正ループ                  | 各22,416ケース。位置・慣性・ダメージ・壁距離・接触フラグ・音と破片の発生条件を比較する。破片の乱数形状・配置は対象外。                                             |
| `test:source-hover`      | `car_gravide` / `car_bank` / `car_preope` / `car_rotation` の空中分岐 | 浮遊・着地・落下開始・影・斜面力110,700ケース、速度13,603ケース、空中ロール16bit全65,536値。接地中の姿勢行列はこの比較に含まない。                                 |
| `test:source-attitude`   | `car_rotation` 全体、`car_acceralate`                                 | 姿勢26,184ケース、推力43,600ケース。前フレームの機体・影の行列を明示入力するため、SDKの三角関数・行列生成自体は対象外。                                            |
| `test:source-resistance` | `car_resistance`                                                      | 5機体、通常・床ブレーキ、速度0〜2047、32bit慣性・乗算符号境界を含む22,560ケース。前後慣性6成分を比較する。                                                         |
| `test:source-tiles`      | `car_chipeffect` の常時効果                                           | 4枠・grip・lev・ダメージ境界・正負のover・描画周期を含む26,112ケース。ダメージ・床ブレーキ・描画属性・ダメージ音の開始条件を比較し、侵入時効果の状態機械は対象外。 |

これらは個別関数・指定した呼出し手順の比較であり、機体更新全体やGPU / SPUの一致を保証しない。CPU・他機体衝突を含む更新順序、通常走行の侵入時床効果、`Gsys.time` の全体管理、落下の終了フレームには直接照合が残る。

### ロジック・ブラウザの検証

通常のテストコマンドと実行方法は [READMEの「検証」](../README.md#検証) を参照。

- ロジック・素材・課題・記録・入力リプレイ・自動保存を検証する。
- 全9コースのプレイヤー3周、および4難易度×9コース×CPU3枠の単独3周完走を検証する。CPUは落下後の復帰を許可する。
- Chromiumで描画・音声・メニュー・カウントダウン・失敗・ゴール後の進行を検証する。画面遷移には状態注入を使い、全課題の実操作クリアを意味しない。

カメラの遮蔽確認はRED GP第1コースの自動走行60秒を30フレーム間隔で調べた120サンプルに限る。物理ゲームパッドの操作感、PS1実機の映像・PCMとのフレーム単位比較、実機リプレイの軌跡は未検証。
