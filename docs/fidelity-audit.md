## 検証範囲

- 型チェック、lint、整形、ビルド。
- ロジック・素材・課題・記録・入力リプレイ・カード・GP成績の既存テスト。
- 全9コースのプレイヤー3周、および4難易度×9コース×CPU3枠の完走。
- Chromium上の描画・音声、メニュー、カウントダウン・失敗・ゴール後の進行。

この検証は原作とのフレーム単位の完全一致を保証しない。固定小数点/GTEの丸め、描画順と半透明、CPU経路、SPUの補間と残響、日本語BIOSフォントなど、既存の差・近似はREADMEの「移植内容と原作との差」に記載している。カメラの遮蔽検証も、記載したコース・走行・サンプリング範囲に限る。

## 原作C関数との直接比較による追加修正

コースの変換に残っていた連続三角関数・浮動小数点補間を廃止し、`CSDATA.DAT` の半度刻みの角度表、Cの整数除算、算術シフト、`sqr_i`、TMDの16bit頂点と整数法線を使用するよう変更した。区間の終端は次の区間の始端で代用せず、原作が生成した終端を保持する。描画、床裏面、接地、バンク力、加速床、リプレイの固定視点が同じ原作頂点を参照する。

区間選択についても、近傍7列から選ぶ方式を原作の `before` / `next` 接続と半平面判定へ置き換えた。セル選択は `car_getplate` の6段階探索と境界上の比較規則を使用し、接地面の高さは `car_gravide` のローカル整数座標・外積・除算で求める。

`npm run test:source-geometry` は原作C関数本体を直接コンパイルした比較用ライブラリを一時ディレクトリに生成する。比較用に演算を書き直した実装ではなく、同梱ソースの `normal_set` / `make_tmd_line` / `make_tmd_circle` / `sqr_i` / `car_getplate` / `car_gravide` を使用する。PS1の描画・音声APIは呼ばないスタブであり、Cのintは32bit、整数のオーバーフローはラップする設定で実行する。

検証結果：全24コース・471区間について、生成済みデータの頂点96,058個と法線73,088個が一致。セル中央・境界上とその±1原作単位の点を含む107,000点について、TypeScriptの区間・セル・コース内外の判定と接地面高さ／外側の落下基準がCの結果に一致した。TRAININGの接続先が存在しない終端の先は比較対象外。

この直接比較が証明するのは上記のコース形状と静的接地問い合わせの一致であり、機体の全更新・壁衝突応答・GPU/SPU全体の一致ではない。

## 壁衝突と移動の追加照合

壁判定を、次の区間の接線・補間した高さに基づく処理から、`CAR_CTR.C car_wallcheck` の現在区間の頂点・整数法線・SVECTORの16bit演算・32bit乗算／シフトへ変更した。左右とも原作が用いる外側左端の辺へ慣性を射影し、壁法線で位置と慣性を補正する。CPUはmode 1の内側判定を先に実行し、その後mode 0の判定・補正を接触がなくなるまで繰り返す。ゴール後のlev=0は音と破片を抑える一方、原作どおり壁による押し戻しとダメージを保持する。

移動では前後慣性の合計を算術シフトし、原作の `posr` に相当する1/4原作単位の整数位置を保持する。表示・次の判定で使う位置は `posr >> 2` とし、負の値も原作と同じ丸めになる。ゴーストのlev=0は走行中は `car_action` 側の壁判定を使い、ゴール後は `car_enemy` 側へ切り替える。リプレイとゴーストの落下も通常走行と同じ抵抗・重力・姿勢・整数移動処理を使用するよう統一した。

`npm run test:source-walls` により、原作Cの `car_wallcheck` 本体に対して全24コースで52,160ケースが一致した（うち43,682ケースは実接触）。左右・バンク・速度80/81、効果音の境界223/224、高度境界、CPU、ゴール後、負のoverを含む。同じ入力について、整数移動・CPU用内側判定・補正ループを実行するC側の参照呼出し手順とも52,160ケースが一致した。比較対象は補正後の整数位置、前後慣性、ダメージ、左右の距離、接触フラグ、壁イベント、効果音と破片の発生数であり、破片の乱数形状や全フレームの機体更新を証明するものではない。

ゴールした瞬間のフレームも、`car_chipeffect` が設定する `goal_count` を壁応答へ直ちに反映する。ただし呼出し自体はそのフレーム中は `car_action` のmode 0であり、内側のmode 1は次フレームの `car_enemy` へ移ってから使う。壁へ接触しながらゴールするケースで、位置補正・ダメージを残し、壁イベント・音・破片を即座に止めることを検証した。

## 浮遊・着地・落下開始・斜面力の追加照合

`car_gravide` の更新順に合わせ、床効果は前フレームのgripを読み、浮遊・着地処理後にgripを更新するようにした。通常走行のダメージ床音も、更新前のgripで決まった床効果へ同期する。CPUのlev>0はプレイヤーの着地反発・浮遊クッションを適用せず、原作どおり床の浮遊高さへ合わせる。`car_enemy` はlev>0で `car_bank` を呼ばないため、CPUに加えていた斜面力を除いた。

落下開始時は処理を途中で打ち切らず、そのフレームの重力・grip・斜面力・移動を進める。影の表示フラグは原作同様、新たに負のoverが設定される前に評価する。落下開始後は直前のセルの頂点と法線を保持し、移動する機体の位置に対してその平面を再計算する。下にある別の路面へ接地対象を切り替えない。機体のピッチは原作のstatus.vxと同符号であり、旧処理で逆にしていた重力補正も修正した。

速度は浮動小数点平方根の切り捨てから、`car_preope` の32bit慣性和・乗算・算術シフトと `sqr_i(2048)` の探索へ変更した。空中のロールは原作の符号と角度ラップを使い、二つの独立した比較による補正をそのまま適用する。原作の6〜9単位のロールが残る挙動も、滑らかに0へ戻す処理へ置き換えない。

`npm run test:source-hover` の結果：全24コース・6機体について、浮遊高さ・着地境界・落下開始境界・tei・CPU・正負のover・角度ラップを含む254,040ケースが原作Cと一致。比較対象はover、Y位置とposr、前後慣性、tei、ダメージ、grip、影の高さと表示フラグ、着地時の無照明フラグと効果音、斜面力。さらに `car_preope` の速度13,603ケース、`car_rotation` の空中分岐のロール補正について16bit全65,536値が一致した。

接地中の姿勢行列・影の姿勢、落下待機中の全床属性処理、フレーム全体の更新順序と描画・音声の完全一致は引き続き照合が必要。
