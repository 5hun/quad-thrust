# QUAD THRUST — Hover Racing browser port

PS1版Hover Racingの提供ソース `HOVER_SOURCE` とデータ `HOVER120/HOVER.PAC` に基づく、TypeScript / Three.js r180 / WebGL 2のブラウザ移植です。

## 起動

オンライン版は既存の本人限定Sites URLを使用します。ローカル版はNode.js 22.18以降・npm・Python 3を準備し、リポジトリのルートで次を実行してから、ブラウザで `http://127.0.0.1:8765` を開きます。

```sh
npm ci
npm run build
npm start
```

終了はCtrl+C。ビルドにはPython 3も使用します（Windowsでは `py`、その他では `python3`。環境変数 `PYTHON` で実行ファイルを指定できます）。ビルド後は `python3 start-server.py`（Windowsでは `py start-server.py`）だけで起動でき、実行時にnpmやCDNへの接続は不要です。WebGL 2対応ブラウザが必要です。

ES modulesと音声読み込みを使うため、`index.html` の直接ダブルクリックでは動きません。HTTP経由で開いてください。

## 比較用のURLオプション

URLに次のオプションを付けて読み込み直すと、外観・コースを切り替えられます。通常は新しい標準機WHITE HAREを表示します。

| オプション         | 内容                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `?classicmachines` | 全機体を原作モデルで表示。標準機の外観は原作LUSTERへ戻り、機体選択・走行・デモ・リプレイ・ゴーストに共通で適用。 |
| `?classictrack`    | 原作のタイルによるコース表面表示。                                                                               |
| `?classiccourses`  | 原作のコース内容を読み込み。                                                                                     |

併用例: `http://127.0.0.1:8765/?classicmachines&classictrack&classiccourses`。

BLUE GPはオリジナルコースのHarbor Run / Cliff Line / Tidal Ringに置き換えています。3戦目のTidal Ringは、幅広の大バンクとS字、折り返し後にS字を斜めにまたぐ狭い橋を備え、橋の上り坂に加速パネルを配置しています。背景は元の3戦目のものを使用します。`?classiccourses`では原作のコース内容に戻ります。

YELLOW GPの1戦目はオリジナルコースのNight Spanに置き換えています。全幅のジャンプと着地直線、その先で折り返すヘアピン、左右交互に傾く3つのうねりを備えます。ジャンプで横へ飛ぶと、折り返してきた帰り道へ直接降りてヘアピンを省略できます。背景は元の1戦目のものを使用します。

`classicmachines` は表示モデル・舵・噴射口・影の切り替えで、機体名・性能・機体ID・記録や保存形式は変更しません。現在、新モデルがあるのは標準機だけです。各オプションは値ではなく名前の有無で判定し、URLから削除すると通常の表示に戻ります。

## モードと操作

| モード      | 内容                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| GRANDPRIX   | Blue / Yellow / Red GP。各3コースで、1位なら次戦へ進みます。敗北・破壊・落下時は同じ戦を再挑戦できます。 |
| PRACTICE    | コース選択式のCPU3台・3周レース。                                                                        |
| TIME ATTACK | 3周のタイム計測。保持中の同一コースのTAリプレイがあれば、当たり判定のないゴーストと対戦します。          |

最初はBlue GP・PRACTICEと通常4機体を利用できます。Blue GPクリアでYellow GP、Yellow GPクリアでRed GP、Red GPクリアでALPHAを解禁します。コース選択では全9コースを利用できます。

起動直後からQUAD THRUSTのメインメニューを表示し、背景ではCPU4台のデモ走行が続きます。GRANDPRIX・OPTION・難易度・記録種別の選択は同じ表示形式を使い、記録一覧・詳細も含めて同じデモ走行を継続します。GRANDPRIX / TIME ATTACK / OPTIONを直接選べます。メニューは方向キーで選択、Enter / Zで決定、Esc / Xで戻ります。OPTIONから難易度設定・記録閲覧・サウンド・全画面表示の切替を利用できます。

| キー      | 走行操作              |
| --------- | --------------------- |
| Space / ↑ | 加速                  |
| ← / →     | ラダー                |
| Q / A     | 左前 / 左後スラスター |
| E / D     | 右前 / 右後スラスター |
| Shift     | ターボ                |
| S / ↓     | ブレーキ              |
| W / X     | 空中の前傾 / 後傾     |
| Esc / P   | 一時停止              |

E+Aで左急旋回、Q+Dで右急旋回。E+Dで左へ、Q+Aで右へ平行移動します。

標準ゲームパッドはAで加速、Xでターボ、Bでブレーキ、左右スティックの横軸でラダー、縦軸で空中姿勢、LB/LT/RB/RTでスラスター、Startで一時停止。メニューは方向・A・B・Startで操作します。走行中はタッチ操作にも対応しています。

全画面・音声はOPTION内の FULLSCREEN: ON / OFF、SOUND: ON / OFF で切り替えます。全画面中はゲーム画面だけを表示します。画面は通常表示・全画面ともウィンドウに追従し、4:3・16:9・21:9・32:9などの横長表示に対応します。上下の視野を保って左右のコースを広く表示し、タイトル・カップ・OPTION配下の選択メニューは中央16:9以内、機体・コース選択と記録表示は中央4:3、HUDは中央16:9以内に配置します。縦長では4:3の画面を中央に収めます。描画解像度は表示サイズに追従し、高さ1080px・約415万画素を上限とします。デモのBGMは起動時に再生を開始します。ブラウザが自動再生を制限している場合は、最初のクリック／タップまたはキー操作で音声が有効になります。CPU難易度はNORMALで固定です。メニューの切り替え・決定・戻ると、一時停止はキーボード／ゲームパッドで操作します。

## 記録・リプレイ・保存

- 記録はGP（PRACTICEを含む）とTIME ATTACKを分離し、各コースで機体を横断したBEST LAP / TOTALの上位6件を機体とタイムで保持します。
- リプレイは60Hzの操縦入力を記録し、物理・CPU・衝突処理を再実行します。レース後の自動リプレイとTAゴーストに使用します。
- ゴーストありのTAでは、厳密に速く完走した場合だけ対戦記録を更新します。別コースやGP / PRACTICEの完走は保持記録を置き換えます。コースを選ぶだけ、または未完走では置き換えません。ゴーストは原作と同じ条件で自動的に出現します。
- 記録・解禁・難易度は、変更時にlocalStorageの自動セーブ1件へ保存し、起動時に自動ロードします。レース途中からの再開には対応していません。
- リプレイとゴーストはセッション内だけで保持し、ページを閉じるか再読み込みすると消えます。GRANDPRIXでは各レースの後にリザルトを表示し、ENTERで次のレースへ進みます。制覇するとカップクリアと解禁を表示します。TIME ATTACK / PRACTICEでは、ゴール時に保存済み1位とのタイム差を表示します。その後のリザルトでは自分の走りのリプレイを背景に、ラップと記録表（TOTAL / BEST LAPを←→で切替）を表示し、RETRY・CHANGE MACHINE・CHANGE COURSE・QUITを選べます。コースアウトや破壊でも同じリザルトからリトライできます。
- 保存形式はv2です。旧形式からの引き継ぎ、手動保存・読込、スロット選択、ファイル入出力はありません。ブラウザの保存領域を利用できない場合は、セッション内だけで進捗を保持します。

## 移植内容と原作との差

9コースと4機体のTMDモデル、床・側壁・背景・HUDの素材、効果音と11曲のSEQ / VAB音源を使用しています。標準機は独立した4基のポッドを持つオリジナル機体[WHITE HARE](docs/standard-machine.md)へ置き換えています（原作モデルの変換・収録処理は継続）。走行は `CAR_CTR.C` / `CAR_CTR2.C` の60Hz固定更新を基準とし、機体特性・床効果・衝突・浮遊・着地・周回判定を実装しています。解禁と入力形式リプレイも原作ソースに基づきます。

原作バイナリのエミュレーションではなく、ブラウザ向けの再実装です。原作照合の情報源・注意点・検証範囲は [原作照合ガイド](docs/fidelity-audit.md) を参照してください。

### ブラウザ向けの仕様・近似

| 項目           | 原作との相違                                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作・表示設定 | キーボード・標準ゲームパッド・タッチ操作、全画面、HD固定の描画、音声のミュートを備えます。                                                                                                  |
| CPU            | 難易度別の最高速度・追加推力・進行差補正は原作を参照していますが、経路選択・旋回判断・低速時の壁回避はブラウザ版の実装です。落下後は復帰します。                                            |
| 描画           | Three.jsの深度バッファ・照明を使用します。HD固定で透視補正を使用します。原作の描画順、GTEの固定小数点・投影丸め・頂点単位照明、STPビット単位の半透明やGouraud色演算は完全再現していません。 |
| 乱数           | 破片などにはブラウザ用の決定的な乱数列を使うため、原作と同じ配置にはなりません。                                                                                                            |
| 音声           | SEQ / VABをWeb Audio / AudioWorkletで再生します。SPUのガウス補間、リバーブRAM演算、24音発音制限、発音タイミングは完全再現しておらず、残響は畳み込みによる近似です。                         |
| リプレイ形式   | 操縦入力とスティックの中間値をセッション内で保持します。                                                                                                                                    |
| 自動保存       | 進捗・記録・設定をlocalStorageに自動保存し、起動時に自動ロードします。                                                                                                                      |

## 開発

以下のコマンドはリポジトリのルートで実行します。開発にはNode.js 22以降とnpmを使用します。

新しいマシンの制作・調整には、[マシンモデル作成の方針](docs/machine-design.md)を参照してください。形状・比率、配色と素材、操作に対応する造形、実画面での調整手順をまとめています。

新しいコースの設計・調整には、[コース作成の方針とルール](docs/course-design.md)を参照してください。実装前に上面図で合意を得る作成手順と、走行体験、区間構成、バンク・立体交差・パネル配置、実走評価についての一般的な設計指針をまとめています。

| ディレクトリ                  | 内容                                              |
| ----------------------------- | ------------------------------------------------- |
| `HOVER_SOURCE/` / `HOVER120/` | 原作ソース / データ                               |
| `src/`                        | TypeScriptソース。共通の型は `src/types.d.ts`     |
| `public/`                     | 配信用HTML/CSS・同梱Three.jsの原本                |
| `dist/`                       | ビルドで生成する配信ファイル一式（Git管理対象外） |
| `tools/`                      | 原作データの抽出・変換ツール                      |
| `tests/`                      | ゲームロジック・アセット・コース・ブラウザの検証  |
| `extracted/`                  | 原作データの展開先（Git管理対象外）               |

```sh
npm ci
npm run typecheck     # strictモードで型チェック
npm run build         # 原作データの抽出・変換、public/のコピー、TypeScriptのコンパイル
npm test              # ビルドとロジック・アセット・完走テスト
npm start             # Python 3でローカルサーバーを起動
npm run lint
npm run format:check
npm run test:source-geometry # Python 3とCコンパイラを使う原作C関数との直接比較
npm run test:source-walls    # 壁応答・整数移動・補正ループの原作C比較
npm run test:source-hover    # 浮遊・着地・落下開始・斜面力・速度・空中ロールの原作C比較
npm run test:source-tiles    # 常時床効果・落下中の床属性の原作C比較
npm run test:source-resistance # 減速・ブレーキ・32bit符号判定の原作C比較
npm run test:source-attitude # 機体・影の姿勢と推力の原作C比較（行列を明示入力）
```

ゲーム本体は `src/`、配信用HTML/CSSは `public/` を編集します。変更後は `npm run build` を実行してください。ビルドは `dist/` を削除してから、原作データの抽出・アセット変換・`public/` のコピー・TypeScriptのコンパイルを実行します。`dist/` の手編集やコミットは不要です。配信時は生成された `dist/` の内容を使用します。Three.jsとライセンスの原本は `public/vendor/` に同梱しています。

物理・ルール・記録はブラウザとNode.jsテストで共有するため、TypeScriptのnamespaceからグローバルAPIとCommonJS APIを生成します。描画・音声・HUD・ゲーム画面はES modulesです。

`npm ci` / `npm install`でHuskyとlint-stagedのコミット前フックを有効にします。ステージ済みの対応ファイルにPrettierを実行し、失敗時はコミットを中止します。手動整形は `npm run format` です。

### 原作データの再生成

配信用の変換済みデータは `npm run build` ですべて再生成します。

抽出時には原作の加算チェックサム、モデル変換時にはプリミティブの頂点参照と形式を検査します。

### 検証

テストは `tests/**/*.ts` にTypeScriptで記述しています。実行にはNode.js 22.18以降が必要です。Node.jsの型除去機能で直接実行し、`npm run typecheck`で本体と全テストをstrictモードで型チェックします。`npm test`にも型チェックが含まれます。テストはビルド済みの`dist/`を検証するため、個別に実行する前には`npm run build`を実行してください。

原作C関数との直接比較には、抽出済みデータ、Python 3、`cc`が必要です。各 `test:source-*` コマンドの比較対象と限界は [原作照合ガイドの検証範囲](docs/fidelity-audit.md#検証範囲) にまとめています。

`npm test`は物理・床効果・衝突・周回・15課題の条件・ランキング・入力リプレイ・自動保存・復元を検証します。全9コースのプレイヤー、および4難易度×9コース×CPU3枠の単独3周完走も確認します（CPUは落下後の復帰を許可）。

ブラウザ検証はローカルサーバーを起動し、PlaywrightとChromiumを指定して実行します。Playwrightは開発依存に含まれています。既定のPlaywrightを使う場合は、`npx playwright install chromium`でブラウザを準備して`npm run test:browser`を実行できます。既存の環境を使う場合は従来どおり次の引数で指定できます。

```sh
npm run test:browser -- <Playwrightのモジュールパス> <Chromiumの実行ファイル> <URL>
```

同じ引数で `test:menu` / `test:postrace` / `test:phases` / `test:attract` / `test:demo-audio` / `test:ghost` / `test:save` を実行できます。描画・音声、各画面の進行、記録・保存、リプレイ、キーボード・仮想ゲームパッド・モバイル表示を検証します。原作データとの照合には `extracted/` の素材が必要です。

完走・失敗・課題結果などの画面遷移テストには状態注入を使用しており、全課題を実操作でクリアした検証ではありません。物理ゲームパッドの操作感、およびPS1実機の映像・PCMとのフレーム単位比較は未検証です。
